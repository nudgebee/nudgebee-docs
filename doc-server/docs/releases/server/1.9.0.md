# v1.9.0

## What's Changed

### 🔍 Troubleshoot

- feat: Alerts that fire together are now grouped into a single incident, and related alerts stay linked even during alert storms
- feat: New Events view that shows one row per distinct alert instead of listing every repeat
- feat: View the history of past root-cause analyses for an incident, not just the latest one
- feat: Choose which monitoring provider each custom dashboard panel reads from
- feat: Broader Elasticsearch metrics support, including aggregations and more data types
- feat: When a trace search returns nothing, NudgeBee now explains the likely reason
- feat: Log evidence cards now show the exact query that was run, and suggestion banners can be dismissed
- fix: Remediation actions on events now run the same way everywhere and keep a record of what was done
- fix: More accurate incident grouping and impact (blast radius) estimates
- fix: Events for deleted resources now close correctly without losing their severity
- fix: Fixed errors in Elasticsearch metric queries
- fix: Trace filters now only offer fields your trace provider actually supports

### ⚡ Optimization

- feat: Cost allocation and rightsizing recommendations now work for clusters without Prometheus
- feat: Apply AWS EBS gp2 → gp3 volume upgrades directly from NudgeBee
- feat: Optimize improvements: row actions on Configuration findings, finding counts on Security tabs, and an easier-to-find Resolutions section
- feat: Filter and break down the Configuration tab by account
- fix: Persistent volume costs and savings are now priced by the actual cloud storage class (including GCP Hyperdisk Balanced) instead of a flat rate
- fix: Persistent volume rightsizing now works with Elastic Agent storage metrics
- fix: Removed rightsizing recommendations that suggested no actual change
- fix: EBS upgrade recommendations no longer suggest downgrades or unsupported regions
- fix: Optimization tables now warn when savings figures can't simply be added together

### 🔄 Workflow

- feat: Automations are now linked to the incidents they ran on, with run history shown on remediation cards
- feat: Copy Link and Copy JSON actions in the Automations table
- fix: Automations with similar names are no longer mixed up in filters and dry runs
- fix: DNS and WHOIS tasks now tell the difference between an unregistered domain and a network error
- fix: Faster Automation builder

### ☸️ Kubernetes

- feat: The Helm chart now installs the NudgeBee agent by default, creates the first admin user during install, and supports an agent-only setup
  - Note: The 1.9.0 chart ships agent `0.1.24`. A banner suggesting an update to `0.1.25` may appear after install. Upgrading the chart does not upgrade the agent automatically.
- feat: Change a cluster's environment directly from its account card
- fix: Fixed an agent sign-in issue where the first character of the token was dropped
- fix: Webhook callbacks no longer depend on the external ingress
- fix: Fixed vulnerability scanning on self-hosted VMs

### ☁️ Cloud

- feat: Limit an AWS account to selected regions so NudgeBee only scans those regions
- feat: Cloud topology now loads from already-synced data, making it faster
- fix: More complete AWS sync, including standalone ECS tasks and EventBridge resources
- fix: GCP log-alert evidence now uses the filter defined on the alert policy
- fix: Fixed AWS billing sync failures caused by unreadable Cost and Usage Reports (CUR)
- fix: Cloud-account event triggers now show the cloud service name instead of a Kubernetes namespace

### 🤖 AI

- feat: Native Anthropic (Claude) support for AWS Bedrock and the direct Anthropic API, including thinking controls
- feat: Admins can turn model "thinking" mode on or off
- feat: Mark Knowledge Base entries as Fact or SOP, add Type and Context tags, and see which entries were used to answer a question
- feat: Start from ready-made templates when editing the Root Cause Analysis (RCA) format
- feat: Ask Nubi about NudgeBee itself, including features, where to find things, and system status
- feat: Support for GPT-5.6, plus prompt caching to reduce response time and LLM cost
- feat: The new logs agent can be selected as the default for log investigations
- feat: More relevant Knowledge Base answers through improved ranking
- feat: Admins can exclude selected agents from secret detection on outgoing data, and follow-up investigations can be cancelled without losing progress
- feat: The remediation agent now tracks PR review comments it has addressed and keeps PR branches up to date
- fix: Knowledge Base search no longer crashes under heavy load
- fix: Per-tier LLM settings are now respected, with better support for OpenAI-compatible endpoints
- fix: Risky or destructive commands now require explicit approval before they run
- fix: Stronger security for the agent workspace, including blocked access to secrets and tighter container defaults
- fix: GPT-5.x models now fetch live data for quick status questions instead of answering from memory
- fix: Event triage no longer fails on very large traces or label data
- fix: Automated code fixes are now limited to the specific change identified during debugging
- fix: Fixed response formatting for Qwen models

### 🔔 Notifications

- feat: Message Nubi directly in Slack without an @mention, and watch investigation progress update live
- feat: Schedule AI Cost Reports and send them to a dedicated Slack channel
- feat: Daily highlight emails now link straight to each insight; Admin Notifications is renamed to Notification Rules
- fix: Nubi's follow-up questions now appear in the Slack thread, and Mermaid diagrams display correctly
- fix: Daily summary emails now leave out non-critical events, with cleaner formatting

### 🎫 Tickets

- feat: Jira Data Center support with Personal Access Token (PAT) sign-in, ticket creation, and status sync

### 🔌 Integrations

- feat: OpenObserve alert webhook: send OpenObserve alerts into NudgeBee to trigger investigations and workflows
- feat: Elasticsearch integrations now show their default log filters
- feat: Limit Confluence indexing to specific page trees
- feat: Custom field mappings for log integrations, with clear rules for which mapping takes priority
- feat: Feature flags now have readable names, are grouped logically, and show their default state
