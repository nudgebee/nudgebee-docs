# v1.13.0

## Before You Upgrade

### All editions

- **API tokens (breaking):** Send your `sk-nb-…` API token directly as a Bearer token. `POST /api/auth/token` and `POST /api/auth/revoke` have been removed, so scripts and CLI versions that use the old exchange must be updated. Recreate any older token that stops working.
- **Relay MCP sessions:** The relay now stores MCP sessions in Redis by default. Installs without Redis must set `MCP_SESSION_STORE=memory` and run a single relay pod.
- **Relay ingress:** An ingress host with no `paths` now exposes only `/register` and `/status`. Custom paths are kept. If you relied on other public relay paths, list them explicitly.
- **Microsoft Teams:** Teams messages now go through the bot instead of Microsoft Graph. On-prem installs must follow the [Microsoft Teams setup guide](../../integrations/Notifications/msteams.md) and set `MS_TEAMS_BOT_TENANT_ID` and `MS_TEAMS_ACTION_SIGNING_KEY`.
- **Setup Center:** The Setup Center is off by default. Set `UI_ENABLE_SETUP_CENTER=true` to turn it on.

### Community edition

- **Official database and broker images:** PostgreSQL, RabbitMQ, and Redis now use official images instead of the Bitnami subcharts. Existing data is kept. Install fails with an error if your values use Bitnami options that the chart no longer supports.
- **No rollback to 1.12 after RabbitMQ 4 starts:** This upgrade moves RabbitMQ from 3.13 to 4.2. To recover, upgrade to 1.13 again and run `kubectl delete pod -n nudgebee rabbitmq-0`. No data is lost.
- **`helm upgrade --reuse-values` is blocked:** Upgrade with your values file (`-f`) or `--reset-then-reuse-values`.
- **First PostgreSQL start:** PostgreSQL checks text indexes and refreshes collation versions before accepting connections. This takes seconds on a typical install.
