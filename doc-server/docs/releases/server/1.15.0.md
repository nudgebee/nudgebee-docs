# v1.15.0

## Before You Upgrade

### All editions

- **Platform super admin is off by default:** Platform super admin roles only work when the app sets `SUPER_ADMIN_ENABLED=true`. While it is off, a super admin signs in as an ordinary user of their own tenant, and existing super-admin sessions end.
- **llm-server secrets are required:** llm-server won't start with the default `LLM_SERVER_JWT_SECRET` or `RELAY_SERVER_SECRET_KEY`. `LLM_SERVER_TOKEN` must be set on llm-server and the app. The Helm chart generates these values. Custom deployments must set them before upgrading.
- **Nubi's database tools run as a read-only role:** llm-server must connect with the database user that runs migrations, or that role must be granted to llm-server's user. Otherwise the tools refuse to run.
- **New data retention defaults:** Daily cleanup now removes inactive cloud resources after 30 days, resource metrics after 60 days, pod profiles after 30 days, and anomaly and SLO report data after 90 days. Raise the `nb_retention_days_*` settings if you need longer history.
- **Automation safety changes:** Steps can no longer run scripts inside the runbook-server pod (the `local` execution mode), and webhook label mappings and alert-rule action templates can no longer load files. Automations that used either now fail with an error.
- **Permissions:** Custom-role Write no longer grants Execute. Custom roles stay behind the per-tenant **Custom roles** setting in Tenant Settings. Session roles are re-checked every five minutes, and a suspended user's open sessions end.

### Enterprise edition

- **Self-signup is off:** Public self-signup is available only on SaaS with `SELF_SIGNUP_ENABLED=true`, and marketplace onboarding requires a real purchase. Disposable email domains are blocked at self-signup.
- **SAML role mapping:** SAML sign-in no longer makes a user `tenant_admin` when no group mapping matches. With no mapping, roles are left unchanged. With a mapping that doesn't match, the user gets the tenant's default role.
